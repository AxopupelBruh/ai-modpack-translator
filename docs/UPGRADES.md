# Устойчивость перевода к обновлению сборки

Сборка обновляется через CurseForge. Перевод должен это переживать — иначе он
умрёт на первом же обновлении.

> **Главное, что делает перевод живучим:** jar-файлы модов **не патчатся**.
> Весь перевод лежит во внешних слоях — ресурспак, датапак, скрипты. Мод обновился —
> его файлы целы, наш перевод лежит рядом и просто продолжает работать.

---

## Сводная таблица

| Слой | Что при обновлении сборки | Устойчивость |
|---|---|---|
| Ресурспак (lang-файлы) | мод обновляет свой `en_us.json` | 🟢 **выживает** — наш `ru_ru.json` продолжает перекрывать. Новые ключи останутся английскими |
| Ресурспак (книги Patchouli) | мод перезаписывает `assets/<ns>/patchouli_books/` | 🟢 выживает — наши `ru_ru/` лежат рядом |
| KubeJS-переводчик подсказок | мод меняет текст подсказки | 🟡 **мягко** — строка не совпадёт → останется английской, но ничего не сломается |
| Квесты FTB | мод-шифровщик меняет ключ | 🔴 **может сломать главы** |
| Датапак книг | мод меняет лут-таблицу | 🔴 **может перекрыть новое содержимое** |
| Собственный `ru_ru` мода | мод обновляет свою вычитку | 🟡 выживает, но наш может перекрыть его новую версию |

---

## 🟢 Ресурспак — переживает обновление

Наш `assets/<ns>/lang/ru_ru.json` **заменяет** lang-файл мода. Мод обновился —
его `en_us.json` изменился, но наш файл всё равно имеет приоритет и перевод остаётся.

**Что может откатиться:** ключи, которые мод добавил в новой версии. Их в нашем
`ru_ru.json` нет → эти конкретные строки покажутся по-английски.

**Что делать при обновлении:** прогнать аудит остатков заново (§5.1 гайда) —
это те самые новые ключи. Сборка при этом ничем не ломается.

## 🔴 Квесты — главный риск

### Почему это ломается

Файлы квестов часто зашифрованы — префиксом вида `LGQ1:`. Ключ выводится из
констант мода-шифровщика. Если автор обновит
мод и поменяет константы, мод перестанет расшифровывать старые файлы.

**Симптом:** FTB Quests показывает пустые главы или ругается на чтение файла.

### Что делать

1. **До обновления сборки** скопировать `config/ftbquests/quests/` в сторону.
2. Если после обновления квесты сломались — вернуть старую папку (мод снова её прочитает).
3. Перешифровать заново новым ключом (в `reference/linggango/lgq_crypt.py` —
   образец такого инструмента; свой декриптор искать в моде сборки).
4. **Крайний вариант:** удалить переведённые `.snbt` — FTB Quests восстановит
   оригинальные квесты из ресурса мода, но они будут на английском. Перевод квестов
   при этом просто пропадает, а игра — работает.

### Чего точно не делать

Не править зашифрованные квесты открытым текстом — мод их не прочитает, главы пропадут.

## 🔴 Датапак книг — второй риск

### Почему это ломается

Датапак **заменяет** файл лут-таблицы целиком. Мод обновился, его лут-таблица
изменилась (новый сундук, новый лут, новая структура) — а в игре всё равно
работает **старая** версия из нашего датапака.

**Симптом:** из сундука данжа пропала часть содержимого, которой раньше было.

### Что делать

1. После обновления мода — **пересобрать датапак** под новую лут-таблицу:
   переизвлечь страницы, перевести новые, собрать заново.
2. **До** пересборки — датапак-jar лучше **удалить**. Английская книга в сундуке
   безопаснее, чем пропавший сундук.

```bash
python3 fix_books.py extract      # заново достать страницы из модов
python3 fix_books.py build        # собрать датапак с переводами
```

И обязательно — проверка, что кэш переводов покрывает все страницы
(см. `TRAPS.md`, п. 4): урезанный кэш тихо оставляет страницы на английском.

## 🟡 Подсказки (KubeJS) — мягкая деградация

Скрипт сопоставляет английскую строку **по точному совпадению**. Мод изменил
формулировку → строка не совпала → осталась английской.

**Что делать:** после обновления мода прогнать скан `.class` заново
(`javap -c -p <Class>.class | grep -oE 'String [^ ]+'`), сверить со словарём,
добавить новые строки.

Ничего не ломается — просто часть подсказок остаётся на английском.

## 🟡 Собственный перевод мода

У некоторых модов есть свой `ru_ru.json`. Наш пак его перекрывает, потому что наш
последний. После обновления мода его вычитка могла улучшиться — а игрок её не увидит.

**Что делать:** при сборке пака сравнивать модовый `ru_ru` с нашим и **не** перекрывать
непустые модовые значения. Это уже заложено в сборщик — смотри
`reference/linggango/build_resourcepack.py`, ветка `cur is None` / `cur == val`.

## 📋 Чек-лист перед обновлением сборки

- [ ] Скопирован `config/ftbquests/quests/` (или вся папка `config/`)
- [ ] Скопирован `kubejs/client_scripts/ru_tooltip_translator.js`
- [ ] Скопирован наш ресурспак и словари (`work/*_ru.json`)
- [ ] Проверено, что кэш переводов книг полон (0 страниц без перевода)
- [ ] Сохранён список модов, которые обновились (`mods/` до и после)
- [ ] После обновления: прогнать аудит остатков и пересобрать датапак
- [ ] В игре пройдены все главы квестов, JEI/REI, инвентарь, данжи

## Куда публиковать результат

Стоит держать перевод в git: он виден, его можно откатить, и по нему видно,
что именно изменилось между сборками. Рабочая практика:

- репозиторий с готовым переводом + инструкцией по установке;
- `install/` — раскладка «как в инстанс»;
- `data/` — словари (источник правды при пересборке);
- `tools/` — конвейер, которым перевод сделан;
- `docs/` — гайд и план работ.

Шаблон такого README — в `templates/README_TEMPLATE.md`,
сборщик релиза — в `templates/publish_release.py`.
