# Рабочие словари

Эти файлы создают скрипты по ходу работы, в репозитории их может не быть.
Смешивать слои нельзя: у них разный жизненный цикл.

| Файл | Кто пишет | Что это |
|---|---|---|
| `glossary.json` | `glossary_quarantine.py promote` (только руками) | активный глоссарий, подставляется в перевод как `terms` |
| `glossary_candidates.json` | `glossary_quarantine.py add` | карантин: черновик, в перевод **не** идёт |
| `glossary_provenance.json` | `glossary_quarantine.py promote` | происхождение термина: дата, source_id, кто подтвердил |
| `glossary_rejected.json` | `glossary_quarantine.py reject` | отклонённые кандидаты и причина |
| `uncertain_pending.json` | `collect_uncertain.py add` | шутки и идиомы, ждущие решения человека |
| `adaptation_examples.json` | `collect_uncertain.py accept` | принятые решения по шуткам — **не** глоссарий |

Почему карантин: один удачный (или кривой) перевод не должен становиться
источником истины для всей сборки. Порог промоушена — ≥3 упоминания в ≥3
разных строках и ни одного конфликтующего варианта. Конфликт решает человек
или `AUDIT_PROMPT`, не скрипт.

Глоссарий и `adaptation_examples.json` — разные вещи: первый про устойчивые
игровые термины, второй про вкусовую адаптацию шуток и отсылок.
