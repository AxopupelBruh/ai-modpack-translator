# Идеи: что добавить в репозиторий

Список идей, отсортированный по пользе на единицу потраченного времени.
Ничего из этого не сделано — это заготовка для следующих итераций.

---

## 🔴 Высокая польза, мало работы

### 1. `scripts/audit_pack.py` — разведка одной командой
Сейчас разведка — это руками набор команд из гайда. Скрипт должен за один запуск
выдать отчёт:
- версия Minecraft / Forge / загрузчика, версия сборки, число модов;
- сколько неймспейсов и в скольких есть `en_us` / `ru_ru` / свой `ru_ru`;
- квесты: сколько файлов, зашифрованы ли, какой префикс;
- Patchouli-книги: сколько, сколько страниц;
- лут-таблицы с текстом в jar'ах и датапаках;
- какие пакеты стоят и в каком порядке;
- **сразу подсветить риски**: «ванильный ru_ru не встроен», «наш пак не последний»,
  «квесты зашифрованы, декриптор не найден».

Идея: агент получает не «я закомандил 10 строк», а готовый отчёт.

### 2. `scripts/collect_remaining.py` — единый список остатков
Сейчас остатки собираются из четырёх источников в разные файлы. Нужен один
`work/remaining.json` со схемой:

```json
{"source": "lang", "ns": "create", "key": "block.create.xxx",
 "en": "Empowered Furnace", "file": "mods/create-....jar"}
```

и общий для всех источников сценарий: маскирование → перевод → валидация →
запись обратно. Тогда перевод остатков — один цикл, а не четыре.

### 3. `scripts/check_placeholders.py` — валидатор отдельным инструментом
Сейчас валидация встроена в переводчик. Нужен отдельный скрипт, который берёт
любой словарь и говорит: плейсхолдеры потеряны, `§`-коды посыпались,
ZWNJ нарушен, строка без кириллицы, в строке символ без глифа.
Прогоняется по **любому** словарю — в том числе по чужому переводу из репозитория.

### 4. Промт для **аудита** (не только для перевода)
Отдельный промт: «вот список строк, найди среди них те, что остались на
английском или выглядят как калька». Позволяет прогнать вычитку по всему
словарю одним запросом, вместо ручного просмотра 76 тысяч строк.

### 5. Промт для **вычитки**
«Вот словарь. Найди: канцелярит, кальки с английского, непоследовательные
термины, разный регистр в одном термине, грубые/старые слова». Вычитка после
машинного перевода — обязательный проход, иначе игрок читает «увеличивает Вашу
Максимальную Здоровье».

### 6. Скачивание ванильного `ru_ru` по версии
Сейчас руками: `curl https://resources.download.minecraft.net/v1_20_1/assets/minecraft/lang/ru_ru.json`.
Скрипт должен по версии Minecraft сам найти правильный URL (в 1.20.3+ путь
изменился) и положить файл в `work/vanilla_ru_ru.json`. Это же даст глоссарий
терминов ванилы.

## 🟡 Средняя польза, средняя работа

### 7. `scripts/diff_packs.py` — что изменилось между сборками
Для слоя «после обновления сборки»: сравнить старый и новый `en_us` каждого
мода → показать добавленные/удалённые/изменённые ключи. Сразу понятно, что
переводить заново.

### 8. CI: `.github/workflows/verify.yml`
Прогон `verify_all.py` на каждый коммит: md5 jar, целостность zip, полнота
lang-файлов, совпадение id квестов, покрытие шрифтом. Публичный репозиторий
с зелёной галочкой — это и реклама, и защита от случайной порчи.

### 9. `templates/AGENTS.md`
Заготовка `AGENTS.md` для репозитория перевода: правила (не патчить jar,
не переводить бренды, формат lang-файлов, порядок команд), чтобы агент,
открывший репозиторий, сразу работал по правилам.

### 10. Экспорт перевода в PO / Crowdin
Чтобы живые переводчики могли править термины в привычном интерфейсе.
Формат `msgctxt`-совместимый, чтобы термины и контекст не терялись.

### 11. Глоссарий: `scripts/build_glossary.py`
Сбор терминов из lang-файлов → глоссарий с частотой и источником. Есть в
Linggango, но привязан к путям — стоит сделать параметризованным и вынести сюда.

### 12. Сравнение с чужим переводом
`scripts/compare_packs.py`: две сборки переводов одного мода → diff. Показывает,
кто вычитал лучше, и позволяет **не** перекрывать удачную чужую вычитку.

## 🟢 Большая работа, но интересно

### 13. Перевод на другие языки
Движок уже параметризован (`--target`). Осталось: терминология под украинский
и белорусский, проверка `ru_ru` → `uk_ua` полноты файлов, перенос аудита глифов
на `unifont`/другие шрифты.

### 14. Перевод GUI-экранов
Сейчас правило «GUI с зашитым текстом не переводим». Технически это возможно:
мод-ресурспак с JSON-моделями интерфейсов. Отдельный большой проект, но метод
тот же — маскирование + сборка.

### 15. Перевод структур и advancement-описаний
В датапаках модов бывают `advancements` с описаниями и `structures` с подписями.
Логика та же, но формат другой.

### 16. Веб-редактор терминов
Простой локальный сервер: таблица терминов, поиск, правка, экспорт в словарь.
Сейчас термины правятся в JSON руками — неудобно.

### 17. Автопроверка в игре
KubeJS-скрипт, который при старте проходит по JEI/REI и выписывает в лог
непереведённые строки с указанием предмета. Даёт точный список остатков
без ручного прохода по сборке.
