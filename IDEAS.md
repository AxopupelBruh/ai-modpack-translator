# Идеи: что добавить в репозиторий

Список идей, отсортированный по пользе на единицу потраченного времени.
Сделанное вычеркнуто и вынесено в конец файла.

---

## ✅ Сделано

- **`scripts/audit_pack.py`** — разведка одной командой: версии, объём по слоям,
  что уже переведено, шифрование квестов, книги Patchouli, лут-таблицы, порядок
  паков и сразу блок «Риски». Проверено на Linggango: 430 модов за 2 секунды.
- **`scripts/check_translation.py`** — валидатор отдельным инструментом.
  Принимает словарь `{en: ru}`, пару lang-файлов или готовый `pack.zip` (+ `--mods`).
  Различает `error` / `warn` / `info`: на 34 501 строке дал 0 блокеров и 1 511
  предупреждений — и по дороге нашёл реальные баги в уже выпущенном паке.
- **`prompts/AUDIT_PROMPT.txt`** — промт аудита готового перевода (а не перевода).
- **`prompts/PROOFREAD_PROMPT.txt`** — промт вычитки стиля.
- **`prompts/RECON_PROMPT.txt`** — промт разведки сборки.
- **`docs/HARDCODED.md` + `scripts/dump_hardcoded.py`** — разбор мода на
  захардкоженный текст и оценка объёма работ.
- Системный промт вынесен из кода в файл: `deepseek_backend.py` читает
  `prompts/SYSTEM_PROMPT_EN_RU.txt`, копии в коде больше нет.
- **`scripts/roles.py` + `scripts/translate_by_role.py`** — роль строки считается
  по ключу, а не моделью, и пачки идут отдельно по ролям; дедупликация одного
  текста до отправки.
- **`scripts/lint_calc.py`** — линтер однозначных калек без модели, до аудита.
- **`scripts/back_translate.py`** — обратный перевод RU→EN для строк с механикой:
  ловит перевёрнутый знак эффекта, потерянное отрицание, съехавшие числа.
- **`scripts/glossary_quarantine.py`** — кандидаты в глоссарий копятся в карантине,
  промоушен только вручную, с записью происхождения.
- **`scripts/collect_uncertain.py`** — шутки и идиомы идут на ручную адаптацию,
  а не в основной перевод.
- **`verify_all.py` блок 6** — проверка «одна EN-строка — один перевод» по всем
  словарям сразу.
- Шапки `# PROMPT_NAME / # STAGE / # INPUT` в начале всех четырёх промтов.

## 🔴 Высокая польза, мало работы

### 1. `scripts/collect_remaining.py` — единый список остатков
Сейчас остатки собираются из четырёх источников в разные файлы. Нужен один
`work/remaining.json` со схемой:

```json
{"source": "lang", "ns": "create", "key": "block.create.xxx",
 "en": "Empowered Furnace", "file": "mods/create-....jar"}
```

и общий для всех источников сценарий: маскирование → перевод → валидация →
запись обратно. Тогда перевод остатков — один цикл, а не четыре.

### 2. Скачивание ванильного `ru_ru` по версии
Сейчас руками: `curl https://resources.download.minecraft.net/v1_20_1/assets/minecraft/lang/ru_ru.json`.
Скрипт должен по версии Minecraft сам найти правильный URL (в 1.20.3+ путь
изменился) и положить файл в `work/vanilla_ru_ru.json`. Это же даст глоссарий
терминов ванилы.

## 🟡 Средняя польза, средняя работа

### 3. `scripts/diff_packs.py` — что изменилось между сборками
Для слоя «после обновления сборки»: сравнить старый и новый `en_us` каждого
мода → показать добавленные/удалённые/изменённые ключи. Сразу понятно, что
переводить заново.

### 4. CI: `.github/workflows/verify.yml`
Прогон `verify_all.py` и `check_translation.py` на каждый коммит: md5 jar,
целостность zip, полнота lang-файлов, совпадение id квестов, покрытие шрифтом,
0 блокеров перевода. Публичный репозиторий с зелёной галочкой — это и реклама,
и защита от случайной порчи.

### 5. `templates/AGENTS.md`
Заготовка `AGENTS.md` для репозитория перевода: правила (не патчить jar,
не переводить бренды, формат lang-файлов, порядок команд), чтобы агент,
открывший репозиторий, сразу работал по правилам.

### 6. Экспорт перевода в PO / Crowdin
Чтобы живые переводчики могли править термины в привычном интерфейсе.
Формат `msgctxt`-совместимый, чтобы термины и контекст не терялись.

### 7. Глоссарий: `scripts/build_glossary.py`
Сбор терминов из lang-файлов → глоссарий с частотой и источником. Есть в
Linggango, но привязан к путям — стоит сделать параметризованным и вынести сюда.
Карантин и ручной промоушен уже готовы (`glossary_quarantine.py`), не хватает
только автоматического сбора терминов из lang-файлов сборки.

### 8. Сравнение с чужим переводом
`scripts/compare_packs.py`: две сборки переводов одного мода → diff. Показывает,
кто вычитал лучше, и позволяет **не** перекрывать удачную чужую вычитку.

## 🟢 Большая работа, но интересно

### 9. Перевод на другие языки
Движок уже параметризован (`--target`). Осталось: терминология под украинский
и белорусский, проверка `ru_ru` → `uk_ua` полноты файлов, перенос аудита глифов
на `unifont`/другие шрифты.

### 10. Перевод GUI-экранов
Сейчас правило «GUI с зашитым текстом не переводим». Технически это возможно:
мод-ресурспак с JSON-моделями интерфейсов. Отдельный большой проект, но метод
тот же — маскирование + сборка.

### 11. Перевод структур и advancement-описаний
В датапаках модов бывают `advancements` с описаниями и `structures` с подписями.
Логика та же, но формат другой.

### 12. Веб-редактор терминов
Простой локальный сервер: таблица терминов, поиск, правка, экспорт в словарь.
Сейчас термины правятся в JSON руками — неудобно.

### 13. Автопроверка в игре
KubeJS-скрипт, который при старте проходит по JEI/REI и выписывает в лог
непереведённые строки с указанием предмета. Даёт точный список остатков
без ручного прохода по сборке.
